Human-in-the-Loop

Single request,
complete the Human-in-the-Loop

Send a request via API. Get a notification with an interaction link. User clicks a button or fills a form. Your original HTTP long-poll returns the result. That's it.

Terminal — One-request demo 
curl -sS --max-time 120 \
  -X POST 'http://localhost:8080/v1/ask' \
  -H 'Authorization: Bearer change-me' \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "Ask4Me Demo",
    "body": "Click a button to respond.",
    "mcd": ":::buttons\n- [OK](ok)\n- [Later](later)\n:::"
  }'
{
  "request_id": "req_xxx",
  "last_event_type": "user.submitted",
  "data": { "action": "ok", "text": "" },
  "last_event_id": "evt_xxx"
}

How It Works

1

Send Request

Your script or program POSTs to /v1/ask with a title, body, and interaction controls (buttons or JSON Forms schema).

2

Get Notified

Server pushes an interaction link to your notification channel — ServerChan or Apprise. The HTTP request blocks, waiting.

3

Human Interacts

Open the link on phone or browser. Click a button, type text, or fill a form. Submit.

4

Receive Result

The original long-poll returns a JSON response with the user's action and input.

Quickstart

Configuration

Create a .env file with the required variables:

VariableRequiredDescription
ASK4ME_BASE_URLYesPublic base URL for building interaction links in notifications
ASK4ME_API_KEYYesAPI authentication key (Bearer token)
ASK4ME_SERVERCHAN_SENDKEYEitherServerChan notification send key
ASK4ME_APPRISE_URLSEitherApprise notification URLs (e.g. schan://SCT...)
ASK4ME_TERMINAL_CACHE_SECONDSNoCache TTL for re-fetching terminal results (default: 60)
ASK4ME_LISTEN_ADDRNoListen address (default: :8080)

Docker

Docker Run 
docker run -d \
  --name ask4me \
  -p 8080:8080 \
  -v $(pwd)/ask4me.db:/data/ask4me.db \
  -e ASK4ME_BASE_URL=https://your-domain.com \
  -e ASK4ME_API_KEY=your-key \
  -e ASK4ME_SERVERCHAN_SENDKEY=your-sendkey \
  easychen/ask4me:latest
Tip: The SQLite database is stored at /data/ask4me.db inside the container. Mount a host volume to persist data across restarts.

API Reference

POST /v1/ask (nonStream — Default)

The default mode. The request blocks until the user submits or the request expires, then returns a single JSON response.

POST with MCD buttons 
curl -sS --max-time 120 \
  -X POST 'http://localhost:8080/v1/ask' \
  -H 'Authorization: Bearer change-me' \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "Deploy to production?",
    "body": "Click a button to approve or reject.",
    "mcd": ":::buttons\n- [Approve](ok)\n- [Reject](reject)\n:::",
    "expires_in_seconds": 600
  }'

Request Parameters

FieldTypeDescription
titlestringNotification / interaction page title
bodystringMessage body shown in notification and page
mcdstringInteraction control description (buttons + inputs)
jsonformsobjectJSON Forms schema-driven form (ignores mcd if present)
expires_in_secondsintRequest expiration time (default: 3600)
serverchan_action_linksboolEnable clickable Action Links in ServerChan 3 notifications
request_idstringPre-generated request ID (must start with req_)

Terminal Event Types

EventMeaning
user.submittedUser clicked a button or submitted input/form
request.expiredRequest expired without user interaction
notify.failedNotification delivery failed (check channel config)

GET /v1/ask

For environments where setting HTTP headers is difficult. Pass key as a query parameter instead of Authorization header.

GET with query params 
curl -sS --max-time 120 -G 'http://localhost:8080/v1/ask' \
  --data-urlencode 'key=change-me' \
  --data-urlencode 'title=Ask4Me Demo' \
  --data-urlencode 'body=Click a button to respond.' \
  --data-urlencode $'mcd=:::buttons\n- [OK](ok)\n- [Later](later)\n:::'
Security note: Query parameters may be logged by proxies. Prefer POST + Authorization header when possible.

SSE Mode (stream=true)

Receive events in real-time, including request.created which contains the interaction_url.

SSE stream 
curl -N -sS \
  -X POST 'http://localhost:8080/v1/ask?stream=true' \
  -H 'Authorization: Bearer change-me' \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "Ask4Me",
    "body": "Please respond.",
    "mcd": ":::buttons\n- [OK](ok)\n:::"
  }'

SSE output format: data: <Event JSON>\n\n, ending with data: [DONE]\n\n. Response includes X-Ask4Me-Request-Id header.

Resume Waiting with request_id

If your client times out, resume waiting with the same request_id:

Resume after timeout 
curl -sS --max-time 40 -G 'http://localhost:8080/v1/ask' \
  --data-urlencode 'key=change-me' \
  --data-urlencode 'request_id=req_xxx'

MCD Syntax

MCD (Interaction Control Description) defines buttons and inputs for the interaction page. It supports two structures:

Buttons Block

MCD Buttons 
:::buttons
- [OK](ok)
- [Later](later)
- [Reject](reject)
:::

Rules

label is the button text. value appears in the result as data.action. The ending line must be a single :::.

Input Line

MCD Input 
:::input name="note" label="Note" submit="Submit"
:::

Rules

label is hint text above the input. submit is the submit button text. name is parsed but the result still uses data.text.

Buttons + Input Together

Combined MCD 
:::buttons
- [OK](ok)
- [Later](later)
:::

:::input name="note" label="Note" submit="Submit"
:::

Clicking a button or submitting text both complete the interaction. The page shows "Submitted." afterward.

JSON Forms

For complex interactions, provide a jsonforms object with JSON Schema, UI Schema, and optional initial data. When present, the interaction page renders the form and ignores mcd. POST-only.

JSON Forms POST 
curl -sS --max-time 120 \
  -X POST 'http://localhost:8080/v1/ask' \
  -H 'Authorization: Bearer change-me' \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "JSON Forms Demo",
    "body": "Please fill the form.",
    "jsonforms": {
      "schema": {
        "type": "object",
        "properties": {
          "name": { "type": "string", "minLength": 1 },
          "age": { "type": "integer", "minimum": 0 }
        },
        "required": ["name"]
      },
      "uischema": {
        "type": "VerticalLayout",
        "elements": [
          { "type": "Control", "scope": "#/properties/name" },
          { "type": "Control", "scope": "#/properties/age" }
        ]
      },
      "data": { "age": 18 },
      "submit_label": "Submit"
    },
    "expires_in_seconds": 600
  }'

Form submission returns payload in the result:

{
  "action": "",
  "text": "",
  "payload": { "name": "Alice", "age": 18 }
}

UI Extensions

Three custom renderers triggered via the options field — no extra type required:

Collapsible Group

Wrap fields in a collapsible <details> section. Use collapsible: true, defaultOpen, and maxHeight in Group options.

Long Label (Markdown)

Static text with optional scrolling and collapsing. Set markdown: true to render GFM. Sanitized with DOMPurify.

Read-only Block

Bind a string field as non-editable scrollable text. Opt-in with readonlyBlock: true on a Control. Supports Markdown.

SDK & CLI

JavaScript SDK

Uses SSE mode by default. Install: npm i ask4me-sdk

SDK Example 
import { ask } from "ask4me-sdk";

const endpoint = "http://localhost:8080/v1/ask";
const apiKey = "change-me";

const { requestId, result } = await ask({
  endpoint,
  apiKey,
  payload: {
    title: "Ask4Me Demo",
    body: "Click a button or type a reply.",
    mcd:
      ":::buttons\n" +
      "- [OK](ok)\n" +
      "- [Later](later)\n" +
      ":::\n\n" +
      ":::input name=\"note\" label=\"Note\" submit=\"Submit\"\n" +
      ":::",
    expires_in_seconds: 600
  },
  onEvent: (ev) => {
    process.stdout.write(`${JSON.stringify(ev)}\n`);
  }
});

console.log("request_id:", requestId);
console.log("final:", result);
